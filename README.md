# Sabai Clay CRM

Мобильная CRM гончарной студии: бронирования, изделия и выдачи, фотографии,
расходы, сертификаты, абонементы и приглашенные мастера. Основное использование
на iPhone, в том числе через «На экран Домой».

## Передача и срок

Текущее размещение и сопровождение заканчиваются **21 ноября 2026 года
включительно, по времени Якутска (UTC+9)**. Получатель отвечает за запуск
собственных сервисов до этой даты. Готовность нового размещения срок не продлевает.
Отключение выполняется отдельно: автоматического таймера нет.

Это полная копия кода для передачи с новой публичной историей Git.
Функции приложения не сокращены. Полный зашифрованный комплект доступен в
[Releases](https://github.com/Shteinyr/sabai-clay-crm-handover/releases/latest):
база, фотографии, исходная история Git, автономная копия проекта и временные
проектные доступы для самостоятельной свежей выгрузки.
Пароль передается отдельно и не публикуется.

Получатель самостоятельно создает свои Supabase, Google OAuth и размещение.
Поддержка и повторные выгрузки прежним владельцем после передачи не предусмотрены.
До отключения старых сервисов получатель отвечает за переключение и сохранение
свежих изменений. Архив фиксирует дату выгрузки, а не автоматически обновляется.
Процедура: [HANDOVER.md](docs/HANDOVER.md).
Первый шаг следующего Codex: прочитать [AGENTS.md](AGENTS.md).

## Получателю

1. Скопировать репозиторий в свой аккаунт или скачать код ZIP и открыть в Codex.
2. Прочитать AGENTS.md и docs/HANDOVER.md; скачать комплект из Releases,
   получить пароль отдельно, расшифровать и проверить контрольные суммы.
3. Создать свои сервисы. Перед переключением остановить ввод в старую базу,
   самостоятельно получить свежую выгрузку по инструкции и восстановить ее.
4. Настроить собственный Google-вход и администратора, опубликовать frontend,
   сверить данные и права. Переключить сотрудников на новый адрес до 21 ноября.
   После перехода пользоваться только новой базой.

Не публиковать расшифрованный комплект, пароль, исходный git-bundle или .env.
Публичный код не предоставляет доступ к аккаунтам прежнего владельца.

## Устройство

- React 19, TypeScript 6, Vite 8; Lucide, Supabase JS, SheetJS, Playwright.
- Frontend статический. Vercel не хранит рабочую базу.
- Supabase Postgres хранит сущности, историю и снимки; Storage хранит файлы фото;
  Supabase Auth обеспечивает Google-вход.
- Рабочие таблицы: clients, appointments, deals, payments, expenses,
  fixed_expenses, certificates, appointment_photos, guest_masters, memberships,
  membership_redemptions. staff_profiles определяет сотрудников.
- audit_log, daily_snapshots, app_state_history сохраняют историю. app_state
  остается архивным форматом, но используется и как fallback загрузки.

## Логика

- «Сегодня»: записи дня и списки открытых, просроченных, к оповещению.
- «Календарь»: недельная навигация, фильтры, статус изделия, фотографии,
  преподаватель, гости и сумма. Сделка связана с записью; отдельной нижней вкладки
  сделок нет. Выданные и закрытые изделия исключаются из напоминаний.
- Ориентир готовности обычно визит + 21 день; окно напоминаний за 3 дня до срока
  и до 5 дней после. Это ориентир, не автоматическое изменение статуса.
- «Финансы»: месячные кассовые доходы, ручные расходы плюс доли приглашенных
  мастеров, прибыль и маржа. Постоянные расходы справочные: не вычитаются
  автоматически из прибыли. Алину и Настю можно анализировать отдельно.
- Приглашенный мастер: имя и ставка сохраняются снимком в занятии. Доля
  считается после выхода из «Бронь». Смена базовой ставки не меняет историю.
- Сертификат: продажа и использование отдельно; деньги не считаются повторно.
- Абонемент: пакет, баланс либо безлимит. Продажа один раз дает доход;
  посещение списывает остаток, но не дает повторный доход. Доля гостевого мастера
  идет в расходы месяца посещения. Списание/возврат выполняется атомарным RPC.
- Excel: восемь листов за всю историю, строгая постраничная загрузка;
  без контактов и фото. Это отчет, **не backup**.

## Запуск

Node.js 24, npm и Git. Из корня клона:

```bash
npm ci
cp .env.example .env.local
npm run dev -- --host 127.0.0.1
```

В .env.local указать **свой** URL и публичный ключ Supabase. Перезапустить Vite.
Без обеих переменных dev-режим является пустой локальной демонстрацией с
localStorage, не рабочей базой студии. В production отсутствие настройки
останавливает запуск понятным сообщением. Secret/service-role ключ нельзя
передавать в VITE-переменных. Поддерживается также VITE_SUPABASE_ANON_KEY.

## База и вход

Для переноса студии восстановить **полный архив**, не запускать импорт из
Excel/app_state. Только для совершенно пустой студии однократно выполнить
supabase/schema.sql. Каталог migrations содержит исторические добавочные
миграции, не полный initial baseline.

Подключить собственный Google OAuth в Supabase Auth и разрешить свой frontend
URL. Создать сотрудников/администратора через staff_profiles по инструкции.
Встроенного списка email с правами нет. Без активного разрешенного профиля
изменения запрещены. Публичное чтение части CRM и фото сохранено намеренно;
скрытие кнопок не делает эти сведения приватными.

## Публикация

Vercel: импортировать свой репозиторий в своем аккаунте, framework Vite,
установка npm ci, сборка npm run build, output dist, Node 24.
В Production/Preview задать свои VITE_SUPABASE_URL и публичный ключ, пересобрать.
Чужую локальную папку .vercel не переносить.

Другой статический хостинг: HTTPS, отдача dist, fallback маршрутов на index.html,
корректный MIME для JS и manifest. HTML не кешировать бессрочно; hashed assets
можно кешировать. Vite встраивает переменные **во время сборки**, не при открытии
страницы. Google redirect должен соответствовать конечному URL.

## Реальные ограничения

- Обычная загрузка таблиц без постраничности: стандартный лимит Supabase может
  обрезать большие таблицы. Excel использует отдельную строгую пагинацию.
- Ошибка нормализованной загрузки или пустые таблицы могут включить fallback
  старого app_state. Это потенциально устаревшие данные, не источник восстановления.
- Общее сохранение отправляет набор сущностей; merge и версии не дают полной
  гарантии конфликтов для всех операций. Атомарная защита абонементов не означает
  такую же защиту любой записи/расхода.
- Браузерный кэш не backup; у нового Supabase отдельный ключ кэша. При ошибке не
  удалять localStorage до диагностики и сохранения копии.
- Наличие daily_snapshots не подтверждает работающий ежедневный планировщик.
  Регулярный административный backup организует получатель.
- PWA без offline service worker; для облака нужен интернет.
- Ранее сообщалось о черном/белом экране. Chromium не воспроизвел проблему;
  конкретный iPhone требует приемки. Error boundary показывает React-ошибку,
  но не ловит отсутствие JS/сеть до запуска React.

Архивы, фото, .env, .vercel и пароли не публикуются. .env.example без секретов.
