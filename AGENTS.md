# Инструкция следующему Codex

Сначала прочитать README.md и docs/HANDOVER.md. Это рабочая CRM студии, данные
не демо. Старое размещение заканчивается 21 ноября 2026 включительно (Якутск).
Публичный репозиторий содержит весь код, но начинает новую историю Git.
Исходная история, рабочие данные и временные проектные доступы находятся в
зашифрованном комплекте из Releases. Их не публиковать в расшифрованном виде.
После передачи прежний владелец не консультирует и не делает новые выгрузки:
получатель самостоятельно разворачивает сервисы и сохраняет свежие изменения.

## Карта

- src/App.tsx: экраны, формы, статусы, зеркалирование сделок/платежей, фото.
- src/components/Memberships.tsx: формы и список абонементов.
- src/data/types.ts: контракт данных.
- src/data/normalizedSupabase.ts: строки, загрузка/сохранение, soft delete,
  RPC абонементов, отдельная строгая загрузка отчета.
- src/data/financeMetrics.ts: общий расчет финансов и долей мастеров.
- src/data/membershipLogic.ts: остатки, сроки, экономическая стоимость.
- src/data/statisticsReport.ts, reportPagination.ts: Excel и пагинация.
- src/hooks/useSyncedAppData.ts: localStorage, merge, отложенное сохранение.
- src/hooks/useAuthProfile.ts: Google-вход, права только из staff_profiles.
- src/data/supabaseClient.ts: явная настройка подключения и ключ кэша.
- src/main.tsx, components/AppErrorBoundary.tsx: запуск и ошибки.
- supabase/schema.sql: bootstrap **пустой** студии.
- supabase/migrations: исторические добавочные миграции, не baseline.
- scripts/handover: административная выгрузка и шифрование.
- tests: локальные сценарии; не использовать рабочую базу.

## Не нарушать

1. Не запускать npm run seed, npm run migrate:supabase, импорт из app_state,
   Excel/кэша на рабочую базу. Не обходить ALLOW_LEGACY_APP_STATE_MIGRATION.
2. До миграции/переноса полный backup Postgres и Storage с проверкой восстановления.
   Перед переключением остановить внесение изменений и сделать **новый** архив.
3. Не удалять физически историю и использованные сущности. Сохранять deleted_at,
   версии и аудит. Не менять финансовые данные ради визуальных исправлений.
4. Подключения только явные. Не переносить .vercel и пароли прежнего владельца.
5. Не расширять публичный доступ, не возвращать встроенные email-роли.
   RLS проверяет активный staff_profiles; UI не заменяет RLS.
6. Не дублировать доход посещений абонементов/сертификатов и производные доли
   мастеров ручными расходами.
7. Фото переносить с исходными bucket/path. URL строится из текущей настройки,
   не старого сохраненного url. Максимум две фотографии в записи.
8. Не обещать полную optimistic locking, приватность чтения или ежедневный backup:
   фактические ограничения в README.
9. Не отключать сервисы автоматически. Удаление облачной базы только отдельным
   решением после проверки последнего полного архива.

## Перед публикацией

Чистый клон: npm ci, lint, build, npm test, node --test tests/handover-tools.test.mjs.
Браузерные тесты без production env на отдельном свободном порту.
Изменения денег: точные суммы, брони/визиты, месяцы, абонементы, сертификаты,
гостевые доли, перезагрузка, два устройства. UI: 390 px, WebKit, ошибки консоли,
safe-area и нижнее меню. Проверить свой URL, OAuth и права гостя/сотрудника/админа.
Отдельно сообщать локальную проверку, публикацию и требуемую приемку получателем.
Зеленые локальные тесты не равны проверке настоящего Google-входа.
